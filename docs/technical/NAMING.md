# Правила именования и моделей

Обязательные соглашения проекта, закрепляющие согласованные с владельцем правила. Применяются к новому коду и изменениям существующего кода.

## Пакеты и файлы

Код размещается в общих пакетах под `ru.gamestelegrambot`: `entity`, `model`, `repository`, `service`, `config`, `mapper`. Корни пакетов по функциональным областям (`economy`, `game.dice`) не используются.

Типы именуются в `PascalCase`, функции и свойства — в `camelCase`, константы — в `UPPER_SNAKE_CASE`. Каждый класс модели находится в отдельном файле с совпадающим именем: `DuelBank` в `DuelBank.kt`.

## Сущности и модели

Базовое имя сущности образуется от имени таблицы в единственном числе и `PascalCase`. К нему добавляется суффикс `Entity`. Соответствующая модель приложения использует то же базовое имя без суффикса. Не следует давать одной и той же сущности разные смысловые имена только из-за различия слоёв.

| Таблица | JPA-сущность | Модель приложения |
| --- | --- | --- |
| `pvp_wallet` | `PvpWalletEntity` | `PvpWallet` |
| `duel_bank` | `DuelBankEntity` | `DuelBank` |
| `duel_invitation` | `DuelInvitationEntity` | `DuelInvitation` |
| `pvp_ledger` | `PvpLedgerEntity` | При необходимости — `PvpLedger` |
| `users` (пример) | `UserEntity` | `User` |

Названия `WalletBalance` и `DuelFunds` для моделей, соответствующих `PvpWalletEntity` и `DuelBankEntity`, больше не используются. Отдельная проекция или самостоятельное понятие может иметь собственное содержательное имя; правило совпадения относится к соответствующим представлениям одного понятия. Создавать модель без потребителя не требуется.

Чистые игровые модели не требуют таблиц или сущностей: `DiceMatch`, `DiceRound`, `SeriesFormat`, `MatchSide`. Не добавлять к моделям суффиксы `Model` или `Entity`.

Встраиваемые идентификаторы (`@Embeddable`) не являются сущностями и имеют суффикс `Id`, например `WalletId`.

## Репозитории, сервисы и конфигурация

Использовать суффиксы по роли: `PvpWalletRepository`, `DuelInvitationService`, `EconomyConfiguration`. Репозитории выполняют доступ к данным, сервисы содержат бизнес-правила и границы транзакций. Имя метода описывает действие: `accept`, `recordRound`, `claimRecovery`.

## Мапперы

Преобразования сущностей в модели находятся в отдельных файлах общего пакета `mapper`: `PvpWalletMapper.kt`, `DuelBankMapper.kt`, `DuelInvitationMapper.kt`.

Использовать extension-функции с явным типом результата и именованными аргументами:

```kotlin
fun DuelBankEntity.toModel(): DuelBank =
    DuelBank(
        id = id,
        chatId = chatId,
        firstPlayerId = firstPlayerId,
        secondPlayerId = secondPlayerId,
        stake = stake,
        status = status,
        winnerId = winnerId,
    )
```

Сервисы импортируют и вызывают `toModel()`. Не объявлять в сервисах приватные преобразования `snapshot()`. Мапперы переносят данные; сравнение результатов, подсчёт очков и расчёт выплат остаются в сервисах.

## Изменяемость

Сохраняемые свойства JPA-сущностей и встраиваемых объектов объявляются как `var`, включая идентификаторы, заполняемые провайдером. `val` не используется для обозначения неизменяемости сохраняемого состояния. Ограничения колонок, например `updatable = false` у журнала операций, сохраняются.

Первичный ключ и его составляющие не изменяются после сохранения. Нельзя менять идентификатор, который используется как ключ в `Map` или элемент `Set`.

Модели приложения используют `val`. Для изменения состояния матча возвращается новая модель; сервисы не хранят изменяемое состояние, общее для разных матчей.

## Константы

Фиксированные бизнес-значения и переиспользуемые числовые параметры объявляются в `companion object` с содержательными именами: `MIN_STAKE`, `STARTING_GRANT`, `CURRENCY_SCALE`, `DUEL_BANK_MULTIPLIER`, `DICE_VALUES`.

Использовать `const val` для поддерживаемых Kotlin примитивных значений и строк, `val` для `BigDecimal`, диапазонов и других объектов:

```kotlin
companion object {
    const val CURRENCY_SCALE = 2
    val MIN_STAKE = BigDecimal("10.00")
}
```

Одно правило имеет одно определение: общая минимальная ставка переиспользуется сервисами, а размер стартового гранта передаётся из сервиса в запрос репозитория. Не дублировать эти значения в логике и SQL-запросах.

Обычные нули и единицы счётчиков, тестовые данные и фиксированные значения схемы/миграций не требуют механического выделения в константы. Правила именования веток находятся в [BRANCHING.md](BRANCHING.md).
